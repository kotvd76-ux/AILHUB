# Spanish AI Hub — Технічна документація проєкту

## 1. Призначення проєкту
**Spanish AI Hub** — це вебплатформа для тренування мовних навичок (аудіювання, граматика, телефонні діалоги, вільний чат) з інтеграцією LLM/TTS/STT, орієнтована на запуск у середовищі Keenetic/роутера або локально.

Ключова ідея: один легкий Python-сервер віддає статичний фронтенд та приймає технічні/навчальні логи, а бізнес-логіка і UI повністю реалізовані у браузері (HTML + JS).

---

## 2. Архітектура

### 2.1. Рівні системи
1. **Backend (Bottle, Python):**
   - віддача статичних файлів;
   - ендпоінт стану системи (`/status`);
   - ендпоінт логування (`/log`) з розділенням на `techlog/` і `studylog/`.
2. **Frontend (SPA-подібні сторінки):**
   - окремі HTML-модулі під різні режими навчання;
   - конфігурації та промпти в JS-файлах `*_set.js`;
   - централізована робота з налаштуваннями через `localStorage`.
3. **Інтеграційний шар AI/Audio:**
   - REST-виклики до OpenAI/Google/Anthropic для тексту/оцінювання;
   - Realtime WebSocket-конектори для native audio (Gemini Live та OpenAI Realtime);
   - онлайн та офлайн TTS (Web Speech API fallback).

### 2.2. Деплой-модель
- `start_hub.sh` запускає **4 інстанси** `main.py` на портах `8080/8085/8095/8100` для різних користувацьких директорій (`kvd`, `kgd`, `kov`, `tst`).
- `main.py` автоматично обирає корінь контенту:
  - прод: `/opt/share/nginx/html/<user_dir>`;
  - локально: директорія репозиторію.

## 3. Структура репозиторію та роль файлів

## Сервер і запуск
- `main.py` — вебсервер на Bottle, маршрути `/`, `/status`, `/log`, static catch-all.
- `start_hub.sh` — скрипт оркестрації інстансів.

## Конфігурація
- `sett_set.js` — глобальні налаштування: провайдери, моделі, голоси, ключі localStorage, мовні профілі, дефолти CEFR/тем.
- `logger.js` — клієнтське логування (tech/study), буферизація, відправка в `/log`.

## Модулі навчання
- `listening.html` + `listen_set.js` — модуль аудіювання.
- `verbs.html` + `verb_set.js` — граматичний тренажер (найбільший модуль).
- `phone.html` + `phone_set.js` — телефонні сценарії та розмовні вправи.
- `chat.html` + `chat_set.js` — діагностика рівня, вільний урок, вільне спілкування.

## Realtime Audio
- `gemini_live_connector.js` — WebSocket-клієнт Gemini Live (audio in/out, транскрипти, VAD-сигнали, запис).
- `openai_nad_connector.js` — WebSocket-клієнт OpenAI Realtime (audio chunking, транскрипти, interrupt, запис).

## Сервісні сторінки
- `index.html` — головне меню та панель статусу системи.
- `settings.html` — UI керування API-ключами, моделями, голосами, мовами, параметрами.
- `service.html` — адміністративно-сервісний модуль (інструменти, діагностика, техоперації).

## 4. Backend: детальний опис

## 4.1. `main.py`
### Стартові параметри
Очікує аргументи:
```bash
python3 main.py <user_dir> <port>
```
Якщо аргументів недостатньо — завершує роботу з usage-повідомленням.

### Роутинг
- `GET /` → `index.html`.
- `GET /status` → JSON із приблизним CPU-load (через `/proc/loadavg`) та free RAM (через `free -m`).
- `POST /log` → приймає JSON:
  ```json
  {
    "module": "chat",
    "line": "...",
    "type": "tech"
  }
  ```
  `type` визначає директорію: `techlog/` або `studylog/`.
- `GET /<filename:path>` → статичні файли (має бути останнім маршрутом).

### Логування
- Один файл на день: `YYYY-MM-DD.txt`.
- Структура каталогів:
  - `<LOG_DIR>/techlog/`
  - `<LOG_DIR>/studylog/`

### CORS
Для `/status` і `/log` виставляється `Access-Control-Allow-Origin: *`, що спрощує доступ із фронтенду в multi-origin сценаріях.

## 4.2. `start_hub.sh`
- Чекає старт системних служб (`sleep 10`), зупиняє попередні `python3`, запускає чотири незалежні інстанси.
- Stdout/stderr кожного інстансу спрямовується у власний `log_auto.txt` у директорії користувача.

---

## 5. Frontend: загальні принципи

1. **Без build-кроку**: сторінки використовують CDN-бібліотеки напряму (Tailwind, React/Babel де потрібно).
2. **Конфігурація через JS-об’єкти**: більшість поведінки керується великими config/prompt-файлами `*_set.js`.
3. **Стан користувача в `localStorage`**:
   - API-ключі, активний провайдер/модель;
   - мова UI/цільова мова/допоміжна мова;
   - TTS режим і голос;
   - технічні toggles (debug, логування, cache/stats).
4. **Модульність за сторінками**: кожен режим має власний UI і runtime, але спільні налаштування читаються через `SETTINGS_CONFIG.storageKeys`.

## 6. Ключові модулі

## 6.1. `settings.html` + `sett_set.js`
**Центр керування платформою.**

Що налаштовується:
- AI-провайдер та модель (OpenAI/Google/Anthropic);
- API-ключі (харкод + ввід у UI + збереження);
- TTS режим (онлайн/offline), голоси, швидкість;
- мовні профілі (UI language, target language, helper language);
- глобальний CEFR default і тематики вправ;
- ключі localStorage для синхронної роботи всіх модулів.

`HARDCODED_KEYS` дозволяє працювати без ручного вводу ключа в браузері (важливо для single-user appliance сценарію).

## 6.2. `logger.js`
Надає 2 класи подій:
- **tech** — технічні діагностики, помилки, стани;
- **study** — навчальні події (відповіді, результати, прогрес).

Патерн:
- формування уніфікованого рядка;
- неблокуюча відправка на `/log`;
- м’яка деградація при offline/помилці сервера.

## 6.3. `chat.html` + `chat_set.js`
Найбільш «AI-native» модуль, має 3 режими:
1. **Тестування** (діагностика CEFR по аспектах: grammar/vocabulary/listening/reading/writing/speaking/pragmatics).
2. **Вільний урок** (LLM веде структуровану сесію з урахуванням рівня).
3. **Вільне спілкування** (корекції помилок через маркери `---КОРЕКЦІЯ--- ... ---КІНЕЦЬ---`).

Особливості:
- React UI без збірки (UMD + Babel);
- debug-консоль у сторінці;
- інтеграція Native Audio Dialog через обидва realtime-конектори.

## 6.4. `listening.html` + `listen_set.js`
Спеціалізований модуль аудіювання:
- генерація/отримання аудіо-тексту для TTS;
- сценарій «прослухай → дай відповідь → отримай фідбек»;
- врахування CEFR/мовних профілів і тем.

## 6.5. `verbs.html` + `verb_set.js`
Найбільший за обсягом модуль (≈2.7k рядків), фактично mini-engine вправ.

Що є всередині:
- мультивправа (різні exercise types: вибір форми, заповнення, reorder тощо);
- трекінг спроб/балів/прогресбарів;
- генерація/підвантаження задач із анти-повторною логікою seed;
- локальний і серверний трек використаних seed;
- TTS-озвучка завдань (онлайн + offline fallback);
- детальне навчальне логування з контекстом відповіді.

## 6.6. `phone.html` + `phone_set.js`
Розмовний тренажер «симуляція дзвінка»:
- набір сценаріїв за рівнями A1–C1;
- role-play, дебати, перефразування, продовження історії, переклад/інтерпретація;
- промпти параметризуються мовним профілем і CEFR-рівнем.

## 6.7. Realtime-конектори
### `gemini_live_connector.js`
- WebSocket-сесія Gemini Live;
- мікрофонний потік, декодування/відтворення аудіо, транскрипти користувача/асистента;
- обробка життєвого циклу сесії (listening/speaking/error);
- підтримка запису змішаного аудіо сесії.

### `openai_nad_connector.js`
- інтеграція OpenAI Realtime API;
- chunking PCM, події транскрипту, відтворення delta-аудіо;
- `interrupt()` для ручного переривання відповіді (`response.cancel`, `input_audio_buffer.clear`);
- синхронізований запис розмови.

## 7. Потоки даних

## 7.1. Налаштування
`settings.html` → `localStorage` → модулі (`chat`, `verbs`, `listening`, `phone`) читають ці значення під час ініціалізації.

## 7.2. Навчальна сесія
UI-модуль → LLM API (текст/оцінка/генерація) → показ відповіді/фідбеку → подія в `logger.js` → `POST /log` → файл дня.

## 7.3. Realtime audio
Мікрофон браузера → WebSocket realtime API → транскрипт + audio response → динамічний UI + (опційно) запис.

## 7.4. Моніторинг системи
`index.html` періодично запитує `/status` і показує CPU/RAM індикатори на головній сторінці.

---

## 8. Конфігурація, змінні та зберігання

- **CLI-параметри:** `USER_DIR`, `PORT`.
- **ENV:** `HUB_LOG_DIR` — override для кореня логів.
- **localStorage:** ключі задаються централізовано в `SETTINGS_CONFIG.storageKeys`.
- **Дискове зберігання логів:** plaintext по днях, окремо tech/study.

## 10. Сильні сторони реалізації

1. **Проста експлуатація**: без складного бекенду та БД.
2. **Гнучкі промпти**: велика частина методології винесена в конфігураційні JS-файли.
3. **Єдина конфігураційна матриця** (`sett_set.js`) для всіх модулів.
4. **Підтримка realtime-аудіо** у двох провайдерів.
5. **Розділення технічних і навчальних логів** для аналітики.

---

## 11. Технічні ризики та покращення

1. **Безпека API-ключів**
   - ключі в localStorage/харкоді підходять для trusted-середовища, але не для multi-user/public deployment.
   - Рекомендація: винести секрети в серверний проксі/token broker.

2. **Відсутність автентифікації на `/log` і `/status`**
   - зараз endpoints відкриті (CORS `*`).
   - Рекомендація: хоча б shared secret або ACL по IP.

3. **Немає централізованої БД**
   - історія навчання в plain text та localStorage.
   - Рекомендація: додати SQLite/PostgreSQL для прогресу/аналітики.

4. **Монолітні HTML-файли**
   - `verbs.html`, `chat.html`, `settings.html` дуже великі.
   - Рекомендація: поступово винести JS в модулі та додати build pipeline (Vite/Webpack).

5. **Відсутність автоматичних тестів**
   - немає unit/e2e/контракт-тестів.
   - Рекомендація: мінімум smoke-тести API і playwright e2e для критичних сценаріїв.

## 12. Рекомендована дорожня карта

### Етап 1 (швидкий hardening)
- додати auth для `/log`;
- обмежити CORS;
- базова валідація payload-ів логера;
- healthcheck endpoint для readiness/liveness.

### Етап 2 (спостережуваність)
- структурований JSON-log формат;
- ротація логів;
- метрики помилок по модулях/провайдерах.

### Етап 3 (масштабування продукту)
- серверний шар для секретів/білінгу;
- профілі користувачів + persistence прогресу;
- модульна фронтенд-архітектура з повторно-використовуваними компонентами.

---

## 13. Підсумок
Проєкт реалізований як **edge-friendly навчальна платформа**: легкий Python backend + насичений AI frontend із кількома педагогічними режимами та realtime-аудіо. Архітектура добре підходить для персонального/домашнього appliance-сценарію, а основні зони для доробки — безпека секретів, контроль доступу, тестування та модульність великого фронтенду.
